## Vướng mắc / Quyết định kỹ thuật

- **Partial unique index dùng `$in` thay `$ne`**: issue ghi "WHERE status != CANCELLED" nhưng MongoDB partialFilterExpression KHÔNG hỗ trợ `$ne`. Dùng `status: { $in: [FINALIZED, PAID] }` — tương đương ngữ nghĩa, phiếu CANCELLED không vào index nên cho phép chốt lại sau hủy.
- **Lọc theo `invoice.paidAt`** (không `created_at`): invoice schema để `paidAt` không map snake_case (`@Prop({ type: Date }) paidAt`) nên field DB thật = `paidAt`. Đã verify qua `invoice.schema.ts`.
- **`baseSalary` map `base_salary`, `workStatus` map `work_status`** trong staff schema — khi query/đọc bằng Mongoose model dùng tên camelCase (Mongoose tự map), nên `staffModel.find({ workStatus, role })` và `staff.baseSalary` đều đúng.
- **Inject Model trực tiếp** (`InvoiceModel` + `StaffModel`) thay vì Service — chỉ cần đọc aggregate + lookup base salary, tránh coupling thừa theo đúng yêu cầu issue.
- **Snapshot pattern**: phiếu là chứng từ bất biến; không recompute. Sửa sai = cancel + finalize lại.
- **Batch resilient**: dùng `payrollModel.exists` check trước + bắt duplicate-key (race) → đếm vào `skipped`, không throw để 1 staff lỗi không làm hỏng cả batch.
- **Chưa có hạ tầng test**: repo hiện 0 file `.spec.ts`. Acceptance test cases trong issue chưa code tự động — để pending, verify thủ công qua Swagger/seed.
