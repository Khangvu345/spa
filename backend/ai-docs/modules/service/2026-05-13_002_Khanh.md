- [x] Tìm ra root cause: `findAll` filter dùng key snake_case (`is_active`, `unit_price`) nhưng MongoDB document lưu camelCase (`isActive`, `unitPrice`) → query match 0 doc → API trả `data: []`.

## Lý do thay đổi

API `GET /services` không trả ra kết quả dù DB đã có 6 dịch vụ từ seed. Nguyên nhân do hiểu sai cơ chế đổi tên field của Mongoose: `@Prop({ name: 'snake_case' })` không có tác dụng (chỉ `alias` mới tạo virtual getter, mà cũng không đổi tên field lưu trong DB). Document thực tế lưu camelCase, filter dùng snake_case nên không match. Fix bằng cách đồng bộ schema + service + index về camelCase — đây cũng là convention sẵn dùng ở module `employee` (xem `passwordHash`).

---

## Vướng mắc / Quyết định kỹ thuật

- **Convention DB field name:** chốt dùng **camelCase** ở Mongo cho toàn bộ schema NestJS (trừ `created_at`/`updated_at` do `timestamps` option). Không cố ép snake_case vì Mongoose không hỗ trợ rename field qua `@Prop` option. Nếu sau này thật sự cần snake_case ở storage layer, phải dùng custom transform / plugin — out of scope MVP.
- **ERD.md ghi snake_case** chỉ mang tính tham khảo logic; implement thực tế theo Mongoose convention.
- **Không cần migration data**: seed đã insert camelCase từ đầu, fix này chỉ đồng bộ phía query.
