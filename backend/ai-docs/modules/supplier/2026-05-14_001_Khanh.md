## Vướng mắc / Quyết định kỹ thuật

- **Issue #06 vs ERD.md mâu thuẫn về schema:** ERD chỉ có `name/phone/address/notes` đơn giản, nhưng Issue #06 mở rộng thêm `contactPerson/email/taxCode/isActive`. Theo nguyên tắc skill "Issue là source of truth khi code" → **theo Issue #06**.
- **`taxCode` index non-unique:** vì `taxCode` optional (nhiều supplier nhỏ lẻ không có), nếu đặt `unique: true` thì nhiều record giá trị `''` sẽ conflict. Giải pháp: index thường để query nhanh, uniqueness do service check chỉ khi value khác rỗng. (Có thể dùng partial unique index `{ taxCode: { $type: 'string', $gt: '' } }` ở phase tối ưu sau.)
- **Default `limit = 10`** override `DEFAULT_LIMIT = 20` (shared/business-rules) theo Issue #06 SUP-01 "pagination 10 items/page". Các module khác (service) dùng 20 — không đụng vì query DTO của supplier override locally.
- **Folder flat ở `src/modules/supplier/`** chứ không nest `inventory/supplier/` (skill có gợi ý nest). Theo chỉ định Issue #06 mục "Context bổ sung — Folder structure" điểm 6.
- **GET list yêu cầu JWT (không `@Public()`)** — khác với service module dùng `@Public()` cho landing page. Lý do: supplier là internal data, chỉ staff đã login mới xem. POST/PATCH thêm `@Roles(ADMIN)`.
- **Search escape ReDoS:** `query.search.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')` trước khi regex — tránh special chars trong input gây ReDoS.
- **Convention DB field camelCase** (theo log 002 service module) — không dùng `@Prop({ name: 'snake_case' })` cho field thường. Chỉ timestamps dùng option `{ createdAt: 'created_at', updatedAt: 'updated_at' }`.
