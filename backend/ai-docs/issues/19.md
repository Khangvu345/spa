## Nghiệp vụ (User stories)

- **SL-01 Nhập kho:** ADMIN nhập material X số lượng Y từ supplier Z với unitPrice tham khảo
- **SL-02 Xuất kho thủ công:** ADMIN trừ stock với lý do (vỡ, mất, kiểm kê thiếu)
- **SL-03 Xem lịch sử kho:** Filter theo material, ngày, loại giao dịch

- **SL-05 Cảnh báo low stock:** Danh sách material có `stockQuantity <= reorderLevel`

## Acceptance Criteria

### A. Schema `stock_ledger` (MongoDB collection: `stock_ledger`)

```typescript
{
  materialId: ObjectId;          // ref Material, required
  
  // Snapshot info để báo cáo lịch sử không bị ảnh hưởng khi material đổi tên/đổi code
  materialCode: string;          // snapshot
  materialName: string;          // snapshot
  materialUnit: string;          // snapshot ('ml', 'gram', 'piece', 'set')
  
  transactionType: 'IN' | 'OUT_INVOICE' | 'OUT_MANUAL' | 'ADJUSTMENT';
  
  quantityChange: number;        // +N nếu IN/ADJUSTMENT+, -N nếu OUT
                                 // Lưu decimal trực tiếp (vd: -0.01 cho khấu hao đá)
  
  stockBefore: number;           // stockQuantity TRƯỚC khi thay đổi (snapshot)
  stockAfter: number;            // stockQuantity SAU khi thay đổi (snapshot)
  
  // Optional cho IN: thông tin nhập
  supplierId: ObjectId | null;   // ref Supplier (nếu IN)
  supplierName: string | null;   // snapshot
  unitPrice: number | null;      // giá nhập tại thời điểm này (cho IN)
  totalCost: number | null;      // quantityChange * unitPrice (cho IN)
  
  // Reference đến nguồn giao dịch
  referenceType: 'INVOICE' | 'STOCK_IN' | 'STOCK_OUT_MANUAL' | 'ADJUSTMENT' | null;
  referenceId: ObjectId | null;
  
  performedBy: ObjectId;         // ref Staff, người thực hiện
  performedByName: string;       // snapshot
  
  reason: string;                // bắt buộc cho OUT_MANUAL/ADJUSTMENT, optional cho IN/OUT_INVOICE
  
  createdAt: Date;               // KHÔNG có updated_at — ledger bất biến
}
```

**Lưu ý quan trọng:**
- **KHÔNG có `updatedAt`** — ledger entry là immutable. Một khi đã ghi thì không sửa/xóa. Nếu sai → tạo entry ADJUSTMENT mới để bù.
- **Tất cả số snapshot tại thời điểm transaction** — báo cáo lịch sử không bị ảnh hưởng khi material/supplier đổi info sau này.

**Indexes cần tạo:**
- `(materialId, createdAt)` compound — query lịch sử material phổ biến nhất
- `(referenceType, referenceId)` — tìm ledger từ Invoice/Stock In ID
- `transactionType` (filter)
- `createdAt` (sort dashboard)
- `performedBy` (audit)

### C. StockLedgerService

#### Public methods (cho controller)

- [ ] `stockIn(dto, currentUser): Promise<LedgerResponseDto>`
  - **Trong MongoDB transaction:**
    - Verify material tồn tại + isActive → 400 `STOCK_MATERIAL_INVALID`
    - Verify supplier tồn tại → 400 `STOCK_SUPPLIER_INVALID`
    - Snapshot stockBefore = material.stockQuantity
    - `stockAfter = stockBefore + quantity`
    - Update `material.stockQuantity` qua `$inc: { stockQuantity: +quantity }`
    - Insert ledger entry với transactionType='IN', referenceType='STOCK_IN', referenceId=ledger._id (self-ref)
  - Lưu snapshot supplier info, unit price, totalCost = quantity * unitPrice

- [ ] `stockOutManual(dto, currentUser): Promise<LedgerResponseDto>`
  - **Trong MongoDB transaction:**
    - Verify material tồn tại
    - Snapshot stockBefore
    - `stockAfter = stockBefore - quantity` (cho phép âm — admin chịu trách nhiệm)
    - Update `material.stockQuantity` qua `$inc: { stockQuantity: -quantity }`
    - Insert ledger với transactionType='OUT_MANUAL', referenceType='STOCK_OUT_MANUAL'
  - Reason bắt buộc

- [ ] `findAll(query)`:
  - Build filter
  - Sort + pagination
  - Trả ledger entries

- [ ] `findByMaterial(materialId, query)`:
  - Tự động set filter materialId
  - Trả ledger của 1 material

- [ ] `findByReference(referenceType, referenceId)`:
  - Tìm tất cả ledger entry liên kết với 1 invoice / 1 manual transaction
  - VD: 1 invoice PAID trừ 3 material → 3 ledger entries cùng referenceId

- [ ] `getSummary(fromDate, toDate)`:
  - MongoDB aggregation:
    - Group theo transactionType
    - Tính count, totalQuantity, totalCost (cho IN)
  - Return: `{ totalIn: {count, quantity, cost}, totalOutInvoice: {...}, totalOutManual: {...} }`

- [ ] `getLowStockMaterials()`:
  - Query: `materials.find({ isActive: true, $expr: { $lte: ['$stockQuantity', '$reorderLevel'] } })`
  - Populate supplier
  - Trả array

#### Internal helper method (cho Invoice #20)

- [ ] `deductForInvoice(materialId, quantity, reason, referenceId, currentUser, session): Promise<void>`
  - **CRITICAL:** Method này được Invoice service gọi trong transaction của Invoice PAID
  - Nhận `session` parameter để cùng transaction
  - Logic giống stockOutManual nhưng:
    - transactionType='OUT_INVOICE'
    - referenceType='INVOICE'
    - referenceId = invoice._id
    - Stock có thể âm (decision đã chốt: vẫn cho PAID, ghi ledger bình thường)
  - KHÔNG validate material exists (Invoice đã pre-validate)
  - KHÔNG throw nếu stock không đủ — cho phép âm

```typescript
async deductForInvoice(
  materialId: Types.ObjectId,
  quantity: number,
  reason: string,
  invoiceId: Types.ObjectId,
  currentUser: AuthenticatedUser,
  session: ClientSession,
): Promise<void> {
  const material = await this.materialModel.findById(materialId).session(session);
  if (!material) {
    throw new BadRequestException({ code: ERROR_CODES.STOCK_MATERIAL_INVALID });
  }
  
  const stockBefore = material.stockQuantity;
  const stockAfter = stockBefore - quantity;
  
  await this.materialModel.findByIdAndUpdate(
    materialId,
    { $inc: { stockQuantity: -quantity } },
    { session },
  );
  
  await this.stockLedgerModel.create([{
    materialId,
    materialCode: material.code,
    materialName: material.name,
    materialUnit: material.unit,
    transactionType: 'OUT_INVOICE',
    quantityChange: -quantity,
    stockBefore,
    stockAfter,
    referenceType: 'INVOICE',
    referenceId: invoiceId,
    performedBy: currentUser.id,
    performedByName: currentUser.fullName ?? 'Unknown',
    reason,
  }], { session });
}
```

## Context bổ sung từ dev

**Quyết định kỹ thuật đã chốt:**

1. **Stock Ledger đơn giản, KHÔNG FIFO** — đây là quyết định nền tảng của dự án. material.stockQuantity là source of truth, ledger là audit trail. Mọi mutation phải trong transaction.

2. **Transaction BẮT BUỘC cho stockIn / stockOutManual / deductForInvoice** — đảm bảo material.stockQuantity và ledger entry luôn đồng bộ. Nếu MongoDB local chưa replica set → setup Docker Compose 1-node replica set, hoặc dùng Atlas free tier.

3. **Ledger entry IMMUTABLE** — không có updatedAt, không có endpoint UPDATE/DELETE. Nếu ghi sai → ADJUSTMENT entry mới bù.

4. **Snapshot trong ledger** — materialCode, materialName, materialUnit, supplierName, performedByName đều snapshot. Báo cáo lịch sử không bị ảnh hưởng khi entity đổi info.

5. **Stock có thể âm** — quyết định đã chốt: Invoice PAID vẫn cho dù không đủ kho. Admin kiểm kê sau qua ADJUSTMENT. Không reject thanh toán vì lý do kho.

6. **`deductForInvoice` là internal method với session param** — cho Khánh inject ở Invoice #20. Logic gọn để Invoice transaction wrap tất cả: invoice update + multiple stock deductions + multiple ledger entries.

7. **Decimal precision:** lưu trực tiếp không nhân 10000.
   - Lý do: số decimal trong dự án chỉ giới hạn (0.01, 0.05, 0.1) — JS number precision đủ.
   - Nếu sau này phát hiện sai số → migrate sang Decimal128 hoặc nhân 10000.

8. **`StockIn` 1 material/1 request thay vì multi-item:** đơn giản hơn cho FE. Nếu admin nhập 10 material → click 10 lần (mỗi lần có confirm). UX này phù hợp với spa nhỏ.

9. **Low stock endpoint:** UI dashboard ADMIN tự polling mỗi phút (hoặc khi load page). Không cần WebSocket push.

10. **Summary endpoint:** dùng cho dashboard ADMIN. Aggregate group theo transactionType, đếm count + sum quantity + sum cost.

11. **Folder structure:** `src/modules/stock-ledger/` (kebab-case).

12. **Coordination với Khang:** Khánh code Stock Ledger song song với Khang code Customer/Booking. **Hoàn toàn không block nhau.**

13. **Lưu ý cho chính Khánh — Issue #20 sẽ dùng:**
    - Inject `StockLedgerService` vào InvoiceService
    - Khi Invoice PAID: lookup BOM của các items → loop call `deductForInvoice(materialId, deductQty, reason, invoiceId, user, session)` cho từng material
