## API Endpoints

| Method | Path | Mô tả | Auth |
|---|---|---|---|
| GET | `/staff-service-assignments` | List tất cả mapping (có filter) | JWT (mọi role) |
| GET | `/staff-service-assignments/by-service/:serviceId` | Tìm staff phụ trách service X | JWT (mọi role) |
| GET | `/staff-service-assignments/by-staff/:staffId` | Tìm các service staff Y làm | JWT (mọi role) |
| POST | `/staff-service-assignments` | Tạo mapping mới (khi có service mới hoặc staff mới) | `@Roles('ADMIN')` |

## Acceptance Criteria

### A. Schema `staff_service_assignments` (MongoDB collection: `staff_service_assignments`)

```typescript
{
  staffId: ObjectId;          // ref Staff, required
  serviceId: ObjectId;        // ref Service, required
  
  commissionRate: number;     // % hoa hồng (0-100), VD: 15 = 15%
                              // Lưu integer (15) không phải decimal (0.15) để tránh float precision
  
  assignedSince: Date;        // ngày bắt đầu làm dịch vụ này (cho tracking thâm niên nếu cần)
  
  isActive: boolean;          // default true; toggle false khi staff nghỉ hoặc reassign
  
  note: string;               // optional, vd: 'Chuyên viên chính, có thể thay thế'
  
  createdAt: Date;
  updatedAt: Date;
}
```

**Constraints:**
- **UNIQUE constraint `(serviceId)`** — mỗi service chỉ có 1 mapping ACTIVE tại 1 thời điểm. Đảm bảo bằng compound unique index `(serviceId, isActive)` partial index where `isActive=true`.
  - Lý do: theo `DICH_VU_VA_HOA_HONG.md` mỗi service chỉ có 1 chuyên viên.
  - Khi reassign: ADMIN toggle assignment cũ `isActive=false`, rồi POST mapping mới.
- Lookup `staffId` phải tồn tại + `workStatus='ACTIVE'` + `accountStatus='ACTIVE'` khi POST
- Lookup `serviceId` phải tồn tại + `isActive=true` khi POST

**Indexes cần tạo:**
- `staffId` (filter — tìm services của 1 staff)
- `serviceId` (filter — tìm staff của 1 service)
- `isActive`
- Compound partial unique `(serviceId)` WHERE `isActive=true`

### C. AssignmentService (logic)

- [ ] `create(dto)`:
  - Verify `staffId` tồn tại + `workStatus='ACTIVE'` + `accountStatus='ACTIVE'` → 400 `ASSIGNMENT_STAFF_INVALID`

  - Check unique `(serviceId, isActive=true)` → 409 `ASSIGNMENT_SERVICE_ALREADY_ASSIGNED` nếu đã có mapping active cho service này
  - Default `isActive=true`, `assignedSince=now`

- [ ] `findAll(query)`:

  - Populate staff + service
  - Trả full (không pagination)

- [ ] `findByService(serviceId)`:

  - Populate staff + service
  - Helper cho các module khác

- [ ] `findByStaff(staffId)`:
  - Tìm tất cả assignment có `staffId=Y` AND `isActive=true`
  - Trả array (1 staff có thể assign nhiều service)
  - Populate service

- [ ] `findOne(id)`: 404 `ASSIGNMENT_NOT_FOUND`

- [ ] `update(id, dto)`:
  - Verify assignment tồn tại
  - Nếu sửa `staffId`: verify staff mới hợp lệ
  - Nếu sửa `serviceId`: check unique constraint
  - Apply dto

## Context bổ sung từ dev

**Quyết định kỹ thuật đã chốt:**

1. **Mỗi service có 1 chuyên viên duy nhất** — theo `DICH_VU_VA_HOA_HONG.md`. Enforce bằng compound partial unique index `(serviceId)` WHERE `isActive=true`.

3. **`commissionRate` lưu integer (15, 20, 25...) không phải decimal (0.15, 0.20, 0.25)** — tránh float precision. Khi tính: `commission = (servicePrice * commissionRate) / 100`.

4. **KHÔNG có CRUD pagination** — chỉ 6 mapping, list trả full. Nếu sau này spa có nhiều service hơn (>20), revisit và thêm pagination.

5. **Populate staff + service trong response** — vì module khác (Service Order, Invoice) cần info đầy đủ, populate sẵn ở 1 query thay vì gọi thêm 2 query.

6. **Service phải check `staff.role === 'STAFF'`** khi POST — không cho assign service cho ADMIN/OPERATOR. Schema không enforce, service layer xử lý.

7. **`assignedSince` field** — chuẩn bị sẵn nếu sau này có tính thâm niên. Phase 1 mặc định `now`, không dùng đến.

8. **Seed depend staff/service đã seed** — phải chạy theo thứ tự: `seed:suppliers → seed:materials → seed:services → seed:staff → seed:customers → seed:assignments`. Khang nên tạo command master `npm run seed:all` chạy tuần tự.
