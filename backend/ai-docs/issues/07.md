- **MAT-01 Xem danh sách:** ADMIN xem danh sách vật liệu, pagination
- **MAT-02 Tìm kiếm:** Theo tên vật liệu
- **MAT-03 Lọc theo trạng thái:** Filter by isActive
- **MAT-04 Lọc theo loại:** Filter by type (CONSUMABLE / DEPRECIATION)
- **MAT-05 Lọc theo supplier:** Filter by supplierId
- **MAT-06 Sắp xếp:** Theo name, stockQuantity, createdAt
- **MAT-07 Xem chi tiết:** ADMIN xem full info
- **MAT-08 Thêm vật liệu:** ADMIN tạo mới, link với supplier
- **MAT-09 Cập nhật:** ADMIN sửa thông tin
- **MAT-10 Vô hiệu hóa:** Toggle isActive

## API Endpoints

| Method | Path | Mô tả | Auth |
|---|---|---|---|
| POST | `/materials` | Tạo vật liệu mới | `@Roles('ADMIN')` |
| GET | `/materials` | Danh sách (pagination + filter + search + sort) | JWT |
| GET | `/materials/:id` | Chi tiết | JWT |
| PATCH | `/materials/:id` | Cập nhật | `@Roles('ADMIN')` |

> Không có DELETE — `isActive=false` để soft delete, giữ ref cho BOM và stock history sau này.

## Acceptance Criteria

### A. Schema `materials` (MongoDB collection: `materials`)

```typescript
{
  code: string;                  // VD: 'OIL_SUNFLOWER', 'STONE_VOLCANIC' — unique
  name: string;                  // VD: 'Tinh dầu hướng dương'
  description: string;           // optional
  unit: string;                  // 'ml', 'gram', 'piece', 'set' — đơn vị đo
  type: 'CONSUMABLE' | 'DEPRECIATION';  // tiêu hao thẳng hay khấu hao
  unitPrice: number;             // Giá nhập đơn vị, VND, integer, min 0 (giá tham khảo, batch thực tế sẽ ghi ở material_batches sau)
  stockQuantity: number;         // Số lượng tồn hiện tại — chấp nhận decimal cho DEPRECIATION
  reorderLevel: number;          // Ngưỡng cảnh báo nhập thêm, default 0
  expectedUsesPerUnit: number;   // Số lần dùng được/unit (cho DEPRECIATION). VD: 100 (1 bộ đá dùng 100 lần). null/0 cho CONSUMABLE
  supplierId: ObjectId;          // ref Supplier, required
  isActive: boolean;             // default true
  createdAt: Date;
  updatedAt: Date;
}
```

**Indexes cần tạo:**
- `code` (unique)
- `name` (search)
- `supplierId` (filter)
- `type` (filter)
- `isActive` (filter)
- Compound: `(isActive, type)` cho query phổ biến

### B. DTOs

- [ ] `CreateMaterialDto`:
  - `code` (IsString, Matches /^[A-Z0-9_]+$/, length 3-30)
  - `name` (IsString, length 2-200)
  - `description` (IsString, optional, max 1000)
  - `unit` (IsString, length 1-20) — vd 'ml', 'gram', 'piece', 'set'
  - `type` (IsEnum: 'CONSUMABLE' | 'DEPRECIATION')
  - `unitPrice` (IsInt, Min 0)
  - `stockQuantity` (IsNumber, Min 0, default 0) — cho phép decimal
  - `reorderLevel` (IsNumber, Min 0, default 0)
  - `expectedUsesPerUnit` (IsNumber, Min 0, optional) — required nếu type='DEPRECIATION'
  - `supplierId` (IsMongoId)

- [ ] `UpdateMaterialDto`:
  - `extends PartialType(CreateMaterialDto)`
  - Thêm `isActive` (IsBoolean, optional)
  - **Lưu ý:** `stockQuantity` có thể update trực tiếp qua endpoint này → discuss với Vu: có nên cho phép admin sửa stock tay không, hay phải qua stock_ledger? MVP: cho phép sửa tay cho tới khi stock_ledger có (phase 2).

- [ ] `QueryMaterialDto`:
  - `page`, `limit`
  - `search?: string` — match `name` regex case-insensitive
  - `isActive?: boolean`
  - `type?: 'CONSUMABLE' | 'DEPRECIATION'`
  - `supplierId?: string` (MongoId)
  - `sortBy?: 'name' | 'stockQuantity' | 'createdAt'` (default `createdAt`)
  - `sortOrder?: 'asc' | 'desc'` (default `desc`)

- [ ] `MaterialResponseDto`:
  - Toàn bộ field từ schema
  - `supplierId` có thể populate thành object `{ id, name }` (optional) — discuss với Vu

### C. MaterialService (logic)

- [ ] `create(dto)`:
  - Check `code` duplicate → 409 `MATERIAL_CODE_EXISTS`
  - Verify `supplierId` tồn tại và `isActive=true` → 400 `MATERIAL_SUPPLIER_INVALID`
  - Nếu `type='DEPRECIATION'`: require `expectedUsesPerUnit > 0` → 400 nếu thiếu
  - Default `isActive = true`

- [ ] `findAll(query)`:
  - Build filter: search ($regex `name`), isActive, type, supplierId
  - Sort, pagination

- [ ] `findOne(id)`:
  - 404 → `MATERIAL_NOT_FOUND`
  - Optional: populate `supplierId` để FE hiển thị tên supplier mà không cần gọi API thêm

- [ ] `update(id, dto)`:
  - Verify material tồn tại
  - Nếu sửa `code`: check duplicate (trừ chính nó)
  - Nếu sửa `supplierId`: verify supplier tồn tại
  - Nếu sửa `type` sang `DEPRECIATION`: require `expectedUsesPerUnit > 0`
  - Apply dto

## Context bổ sung từ dev

**Quyết định kỹ thuật đã chốt:**

1. **Field `stockQuantity` có trong schema nhưng chưa có logic stock movement** — đây là decision của Vu: "cứ điền field vào còn nối sau được mà". Admin có thể update tay qua PATCH cho tới khi `stock_ledger` được implement (phase 2 Kho). Lưu ý: KHÔNG được mutate `stockQuantity` qua bất kỳ logic nghiệp vụ nào khác trong issue này (vd: không trừ stock khi invoice paid). Đó là phase 2.

2. **2 loại material: CONSUMABLE vs DEPRECIATION** — quan trọng cho BOM sau này:
   - CONSUMABLE: trừ kho thẳng theo định mức (vd: 30ml tinh dầu/ca → trừ 30ml)
   - DEPRECIATION: trừ phân số (vd: 0.01 bộ đá/ca → 100 ca mới trừ 1 bộ)
   - Field `expectedUsesPerUnit` lưu số lần dùng được/đơn vị (chỉ required cho DEPRECIATION)

3. **`stockQuantity` chấp nhận decimal** — vì DEPRECIATION có thể có giá trị 0.5 bộ đá còn lại sau 50 lần dùng.

4. **`supplierId` required** — không cho phép tạo material không có supplier. Lý do: tracking nguồn cung. Nếu cần "không xác định" → tạo supplier "Không xác định" trong seed.

5. **Verify supplier `isActive=true` khi create material** — tránh link material mới với supplier đã ngừng hoạt động. Nhưng KHÔNG cascade: nếu sau này supplier bị `isActive=false`, material vẫn còn → discuss xem có cần warning UI không.

6. **PATCH cho phép sửa `stockQuantity` thủ công** — tạm cho MVP. Sau này khi stock_ledger có → REMOVE field này khỏi UpdateMaterialDto, ép qua endpoint nhập kho riêng.

7. **Populate supplier khi GET detail** — optional, nhưng khuyến nghị có để FE hiển thị tên supplier mà không cần gọi API thêm. Format response:
   ```typescript
   {
     id, code, name, ..., 
     supplierId: '64xxx',
     supplier: { id: '64xxx', name: 'Hương Việt' }  // populated
   }
   ```
   Discuss với Vu format chuẩn.

8. **15 materials seed đầy đủ cho 6 dịch vụ** — sau khi #07 xong, BOM Issue chỉ cần link service ↔ material với standardQuantity.

9. **`unitPrice` là giá tham khảo** — giá thực tế từng lô sẽ ở `material_batches` (phase 2). Field này dùng để tính tạm chi phí dịch vụ cho báo cáo MVP.

10. **Lưu ý cho dev:** Hãy đảm bảo chạy seed Supplier (#06) TRƯỚC khi chạy seed Material (#07), nếu không sẽ lookup `supplierId` về `undefined` và throw error. Best practice: tạo 1 command master `npm run seed:all` chạy tuần tự Supplier → Material → Service.
