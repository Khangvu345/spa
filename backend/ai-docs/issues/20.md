## Nội dung Issue (paste nguyên văn)

## Mô tả

Implement module **Invoice** (Hóa đơn) + logic **Auto Stock Deduction** khi invoice chuyển sang status PAID. Phase 1 chỉ support `paymentMethod=CASH` (VNPay là phase 4 optional).

**Đây là issue tích hợp lớn nhất của dự án** — kết nối 4 modules: Service Order, BOM, Stock Ledger, và (sau này) Salary Records.

**Workflow nghiệp vụ:**
```
Service Order COMPLETED
  ↓
OPERATOR tạo Invoice từ Service Order
  → Invoice status = DRAFT (có thể sửa)
  → Invoice status = PENDING_PAYMENT (đã chốt, chờ khách trả tiền)
  → Khách trả tiền tại quầy → OPERATOR confirm
  → Invoice status = PAID
     ↓
     [TRONG TRANSACTION]
     - Update invoice.status = PAID
     - Update serviceOrder.status = INVOICED  
     - Lookup BOM của từng service item → trừ stock + ghi ledger
     - Snapshot commission cho từng item (cho Issue Salary sau)
     [END TRANSACTION]
```

**Phạm vi giới hạn:**
- ✅ Invoice CRUD với status flow `DRAFT → PENDING_PAYMENT → PAID` / `CANCELLED`
- ✅ Tạo Invoice từ Service Order (1-1 relationship)
- ✅ Auto Stock Deduction khi PAID (transaction wrap)
- ✅ Commission snapshot trong invoice items (chuẩn bị sẵn cho Salary module)
- ✅ Discount overall (field `discountAmount`)
- ✅ paymentMethod = `CASH` only
- ❌ KHÔNG include VNPay integration — phase 4 optional
- ❌ KHÔNG include Salary calculation logic — issue riêng phase 2
- ❌ KHÔNG include in hóa đơn PDF — phase 2B
- ❌ KHÔNG include refund flow — out of scope

## Nghiệp vụ (User stories)

- **INV-01 Tạo invoice từ Service Order:** OPERATOR click "Tạo hóa đơn" trên Service Order COMPLETED → tạo Invoice DRAFT
- **INV-02 Sửa discount:** OPERATOR thêm/sửa discount khi invoice DRAFT
- **INV-03 Chốt invoice:** OPERATOR chuyển DRAFT → PENDING_PAYMENT (không sửa được nữa)

- **INV-05 Hủy invoice:** OPERATOR hủy invoice DRAFT/PENDING_PAYMENT
- **INV-06 Xem danh sách:** Filter theo customer, status, date, mã hóa đơn
- **INV-07 Xem chi tiết:** Full info với items, customer, payment, audit

### A. Schema `invoices` (MongoDB collection: `invoices`)

```typescript
{
  invoiceCode: string;          // unique, 'INV-YYYYMMDD-NNNN'
  
  serviceOrderId: ObjectId;     // ref ServiceOrder, UNIQUE (1-1)
  customerId: ObjectId;         // ref Customer (denormalized từ SO)
  
  // Snapshot từ Service Order
  customerSnapshot: {
    fullName: string;
    phone: string;
    email: string;
  };
  
  // Embed items (snapshot từ Service Order tại thời điểm tạo invoice)
  items: [{
    _id: ObjectId;
    serviceOrderItemId: ObjectId;  // ref item gốc trong SO
    serviceId: ObjectId;
    serviceCode: string;
    serviceName: string;
    unitPrice: number;             // snapshot từ SO
    quantity: number;
    subtotal: number;
    
    // Staff snapshot cho commission calculation
    staffId: ObjectId;
    staffName: string;
    commissionRate: number;        // % integer
    commissionAmount: number;      // = subtotal * commissionRate / 100 (snapshot)
  }],
  
  itemsSubtotal: number;        // sum(items.subtotal) — snapshot từ SO
  extraCharge: number;          // snapshot từ SO
  discountAmount: number;       // OPERATOR áp dụng (VND, integer, ≥0)
  totalAmount: number;          // itemsSubtotal + extraCharge - discountAmount
  
  status: 'DRAFT' | 'PENDING_PAYMENT' | 'PAID' | 'CANCELLED';
  
  paymentMethod: 'CASH' | 'VNPAY' | null;  // null khi chưa thanh toán
                                            // Phase 1 chỉ CASH; VNPAY phase 4
  
  // Audit
  createdBy: ObjectId;
  createdByName: string;
  
  paidAt: Date | null;
  paidBy: ObjectId | null;       // OPERATOR confirm payment
  paidByName: string | null;
  
  cancelledAt: Date | null;
  cancelledBy: ObjectId | null;
  cancelReason: string | null;
  
  note: string;
  
  // Tracking auto deduct
  stockDeducted: boolean;        // true sau khi PAID + deduct xong
  
  createdAt: Date;
  updatedAt: Date;
}
```

### C. InvoiceService

- [ ] `generateInvoiceCode()`: `INV-YYYYMMDD-NNNN`

- [ ] `create(dto, currentUser): Promise<InvoiceResponseDto>`
  - Verify ServiceOrder tồn tại + `status = COMPLETED` → 400 `INVOICE_SO_NOT_COMPLETED`
  - Verify ServiceOrder chưa có invoice (`serviceOrderId` unique) → 409 `INVOICE_SO_ALREADY_INVOICED`
  - Snapshot items từ Service Order:
    - Copy `serviceOrderItem` → invoice item
    - Tính `commissionAmount = (subtotal * commissionRate) / 100` cho mỗi item
  - Snapshot customerSnapshot, itemsSubtotal, extraCharge từ SO
  - Apply discountAmount → `totalAmount = itemsSubtotal + extraCharge - discountAmount`
  - Status = DRAFT, stockDeducted = false

- [ ] `update(id, dto)`:
  - Verify status = DRAFT → 400 `INVOICE_INVALID_STATUS`
  - Apply discountAmount → recalc totalAmount
  - Apply note

- [ ] `finalize(id, currentUser)`:
  - Verify status = DRAFT → 400
  - Status = PENDING_PAYMENT
  - Không cho sửa nữa

- [ ] `markPaid(id, dto, currentUser): Promise<InvoiceResponseDto>`
  - **CRITICAL — TRONG MONGODB TRANSACTION:**
    1. Verify invoice status = PENDING_PAYMENT → 400 `INVOICE_INVALID_STATUS`
    2. Verify `paymentMethod = 'CASH'` (phase 1) → 400 `INVOICE_PAYMENT_METHOD_NOT_SUPPORTED` nếu khác
    3. Update invoice: status=PAID, paidAt=now, paidBy=currentUser, paymentMethod, stockDeducted=true (set TRƯỚC khi deduct để không retry nếu fail nửa chừng — thật ra ngược lại, set SAU khi deduct success... xem context bổ sung)
    4. Update Service Order status=INVOICED qua `serviceOrderService.markAsInvoiced(serviceOrderId, invoiceId, session)`
    5. **Auto Stock Deduction loop:**
       - Build map: `materialId → totalDeductQuantity` từ tất cả items
       - Cho mỗi item trong invoice:
         - Gọi `bomService.findByService(item.serviceId)` lấy BOM entries
         - Cho mỗi BOM entry: `deductQty = bomEntry.standardQuantity * item.quantity`
         - Aggregate vào map
       - Loop qua map, gọi `stockLedgerService.deductForInvoice(materialId, deductQty, reason, invoiceId, currentUser, session)` cho từng material
       - reason = `"Trừ kho từ hóa đơn ${invoice.invoiceCode}"`
    6. **Stock có thể âm OK** — decision đã chốt, không reject
    7. Commit transaction
  - Return invoice updated

- [ ] `cancel(id, dto, currentUser)`:
  - Verify status IN [DRAFT, PENDING_PAYMENT] → 400 `INVOICE_CANNOT_CANCEL_PAID`
  - Update: status=CANCELLED, cancelledAt, cancelledBy, cancelReason

- [ ] `findAll(query)`:
  - Build filter
  - Populate customer (lite version) — KHÔNG populate items (đã embed)
  - Sort, pagination

- [ ] `findOne(id)`: 404 `INVOICE_NOT_FOUND`

## Context bổ sung từ dev

**Quyết định kỹ thuật đã chốt:**

1. **1-1 relationship Service Order ↔ Invoice** — `serviceOrderId` UNIQUE trong invoices. 1 SO chỉ có 1 invoice.

2. **Auto Stock Deduction trong cùng transaction với Mark Paid** — đảm bảo:
   - Nếu deduct fail → invoice không PAID
   - Nếu invoice PAID → deduct đã thành công
   - Service Order status đồng bộ với invoice status

3. **`stockDeducted` flag** — chuẩn bị sẵn cho case refund/cancel-after-paid (out of scope hiện tại). Phase 1: set true khi PAID.

4. **Stock âm OK khi PAID** — decision đã chốt toàn dự án. Admin kiểm kê sau qua ADJUSTMENT.

5. **Commission snapshot tại Invoice creation, KHÔNG tại PAID** — vì commissionRate đã snapshot ở Service Order item, Invoice chỉ copy lại. Khi assignment đổi commissionRate sau → invoice cũ không bị ảnh hưởng.

6. **paymentMethod default null, set khi mark-paid** — vì DRAFT/PENDING_PAYMENT chưa biết khách trả phương thức nào.

7. **Discount validate trong service:**
   ```typescript
   if (discountAmount > itemsSubtotal + extraCharge) {
     throw new BadRequestException({ code: ERROR_CODES.INVOICE_DISCOUNT_EXCEEDS_TOTAL });
   }
   ```

8. **Tạo `Map<materialId, totalDeductQuantity>` trước khi loop deduct** — vì 1 invoice có 2 cùng service (quantity=2) hoặc 2 service khác nhau cùng dùng 1 material → cần aggregate trước, deduct 1 lần / material. Đỡ tạo nhiều ledger entries thừa.

9. **Service order `markAsInvoiced` qua session** — đã chuẩn bị ở Issue #16. Khánh inject `ServiceOrderService` và gọi trong transaction.

10. **Folder structure:** `src/modules/invoice/` (flat).

11. **Test transaction integrity bắt buộc** — đây là critical path. Setup DB local replica set (Docker Compose 1-node) hoặc dùng Atlas. Nếu transaction không work → cả deduct logic vô nghĩa.

12. **Lưu ý cho Khánh khi code:**
    - Order quan trọng trong transaction:
      ```
      1. Update invoice status (lock invoice)
      2. Update SO status (lock SO)
      3. Loop deduct stock (mỗi material 1 lệnh)
      4. Commit
      ```
    - Nếu bất kỳ bước nào throw → rollback tất cả
    - **KHÔNG** gọi `session.commitTransaction()
