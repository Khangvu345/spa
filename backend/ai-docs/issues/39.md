## API Endpoints

| Method | Path | Mô tả | Auth |
|---|---|---|---|
| GET | `/reports/revenue/export-pdf` | Báo cáo doanh thu → PDF | `@Roles('ADMIN')` |

### C. Controller — trả PDF binary

```typescript
@Get('invoices/:id/export-pdf')
async exportInvoicePdf(@Param('id') id, @Res() res) {
  const invoice = await this.invoiceService.findOne(id);
  const buffer = await this.pdfService.buildInvoicePdf(invoice);
  res.setHeader('Content-Type', 'application/pdf');
  res.setHeader('Content-Disposition', `inline; filename="invoice-${invoice.invoiceCode}.pdf"`);
  res.send(buffer);
}
```
> `inline` cho hóa đơn (mở browser xem rồi Ctrl+P in). `attachment` cho báo cáo (tải về).
> ⚠️ KHÔNG wrap ApiResponse envelope — raw binary.

## Context bổ sung từ dev

1. **pdfmake không puppeteer** — nhẹ, không cần Chromium, deploy dễ. Đánh đổi layout đẹp lấy đơn giản.

2. **Font tiếng Việt là rủi ro chính** — Roboto mặc định thường OK nhưng PHẢI test ký tự có dấu. Nếu lỗi ô vuông → nhúng font vào vfs. Đừng để phát hiện lúc demo.

3. **PDF tái dùng data, không tính lại** — báo cáo lấy từ #22, hóa đơn từ #20, phiếu lương từ #21. Nếu số PDF lệch số trên màn hình → bug ở chỗ build PDF, không phải logic.

4. **inline vs attachment** — hóa đơn `inline` (xem + in ngay), báo cáo `attachment` (lưu file). FE mở tab mới trỏ endpoint.

5. **Excel vs PDF** — #22 làm Excel (báo cáo), #25 làm PDF (báo cáo + hóa đơn + lương). Đáp ứng trọn "Excel HOẶC PDF" + "in hóa đơn". Có cả hai là điểm cộng.

6. **Lưu ý FE:** nút "In PDF" → `window.open('/invoices/:id/export-pdf')` mở tab xem → người dùng Ctrl+P. Không cần FE render PDF.
