## API Endpoints

| Method | Path | Mô tả | Auth |
|---|---|---|---|
| POST | `/services` | Tạo dịch vụ mới | `@Roles('ADMIN')` |
| GET | `/services` | Danh sách (pagination + filter + search + sort) | `@Public()` |
| GET | `/services/:id` | Chi tiết | `@Public()` |
| PATCH | `/services/:id` | Cập nhật (bao gồm toggle isActive) | `@Roles('ADMIN')` |

> Không có DELETE — dùng `isActive=false` để vô hiệu hóa (soft delete), giữ data lịch sử cho báo cáo doanh thu.

## Acceptance Criteria

### A. Schema `services` (MongoDB collection: `services`)

```typescript
{
  code: string;              // VD: 'SWEDISH_60', 'HOT_STONE_90' — unique, validate /^[A-Z0-9_]+$/
  name: string;              // VD: 'Massage Thụy Điển'
  description: string;       // Mô tả chi tiết
  price: number;             // VND, integer, min 0
  durationMinutes: number;   // Thời gian thực hiện, min 1
  cleanupMinutes: number;    // Thời gian dọn dẹp, min 0, default 15
  isActive: boolean;         // default true
  createdAt: Date;
  updatedAt: Date;
}
```

**Indexes cần tạo:**
- `code` (unique)
- `isActive` (filter thường xuyên)
- `name` (text index optional, dùng regex là đủ cho MVP)

### B. DTOs

- [ ] `CreateServiceDto`:
  - `code` (IsString, Matches /^[A-Z0-9_]+$/, length 3-30)
  - `name` (IsString, length 2-100)
  - `description` (IsString, max 1000, optional → default empty string)
  - `price` (IsInt, Min 0)
  - `durationMinutes` (IsInt, Min 1, Max 480)
  - `cleanupMinutes` (IsInt, Min 0, Max 120, default 15)
  - `isActive` (IsBoolean, optional → default true)

- [ ] `UpdateServiceDto`:
  - `extends PartialType(CreateServiceDto)` — tất cả field optional
  - KHÔNG cần Omit `code` (admin có thể đổi code nếu chưa dùng)

- [ ] `QueryServiceDto`:
  - `page`, `limit` (chuẩn skill, default page=1 limit=10)
  - `search?: string` — match `name` regex case-insensitive
  - `isActive?: boolean` — filter trạng thái
  - `sortBy?: 'name' | 'price' | 'createdAt'` (default `createdAt`)
  - `sortOrder?: 'asc' | 'desc'` (default `desc`)

- [ ] `ServiceResponseDto`:
  - `id, code, name, description, price, durationMinutes, cleanupMinutes, isActive, createdAt, updatedAt`
  - Tất cả field đều có `@ApiProperty` cho Swagger

### C. ServiceService (logic)

- [ ] `create(dto): Promise<ServiceResponseDto>`
  - Check `code` duplicate → 409 `SERVICE_CODE_EXISTS`
  - Default `isActive = true`
  - Default `cleanupMinutes = 15` nếu không truyền
  - Default `description = ''` nếu không truyền

- [ ] `findAll(query): Promise<{ data, meta }>`
  - Build filter: search ($regex `name` với `i` flag), isActive
  - Sort theo `sortBy` + `sortOrder`
  - Pagination với `Promise.all([find, countDocuments])`

- [ ] `findOne(id): Promise<ServiceResponseDto>`
  - 404 nếu không tồn tại → `SERVICE_NOT_FOUND`

- [ ] `update(id, dto): Promise<ServiceResponseDto>`
  - Verify service tồn tại
  - Nếu sửa `code`: check duplicate (ngoại trừ chính nó)
  - Apply dto fields
  - Return updated entity

### D. ServiceController

- [ ] `POST /services` `@Roles('ADMIN')`
- [ ] `GET /services` `@Public()` — KHÔNG cần JWT (cho landing page)
- [ ] `GET /services/:id` `@Public()` `ParseObjectIdPipe`
- [ ] `PATCH /services/:id` `@Roles('ADMIN')` `ParseObjectIdPipe`

## Context bổ sung từ dev

**Quyết định kỹ thuật đã chốt:**

1. **Field `code` user input, validate unique** — KHÔNG auto-generate. Lý do: Admin cần control code để khớp với seed (vd: `SWEDISH_60` cho frontend hardcode reference). Regex `/^[A-Z0-9_]+$/` ép format đẹp.

2. **GET list và GET detail đều `@Public()`** — landing page khách hàng cần xem dịch vụ trước khi đăng nhập/đặt lịch. KHÔNG cần JWT. Lưu ý đảm bảo `@Public()` decorator chạy đúng (test bằng cách gọi API không gửi Authorization header).

3. **Không có DELETE endpoint** — dùng `isActive=false` để soft delete. Lý do: cần giữ data lịch sử để báo cáo doanh thu, BOM tham chiếu, invoice records.

4. **Seed gộp vào Issue này** — vì 6 dịch vụ là business core, không phải fixture test. Idempotent để chạy nhiều lần không lỗi.

5. **Folder structure:**
   - `src/modules/service/` (folder English noun, collection name `services`)
   - Theo skill `spa-backend-module-pattern`

6. **Giá seed (price)** là **placeholder** — bạn có thể adjust trong PR review hoặc seed lại sau. Đây không phải requirement business, chỉ để demo có data.

7. **`cleanupMinutes` quan trọng cho Slot Availability** sau này — Issue Slot sẽ dùng field này để tính `totalBlockTime = duration + cleanup`. Đảm bảo seed đúng giá trị từ business spec (xem `DICH_VU_VA_HOA_HONG.md`):
   - SWEDISH_60: 60 + 15 = 75
   - HOT_STONE_90: 90 + 20 = 110 (đặc biệt — luộc đá)
   - THAI_90: 90 + 15 = 105
   - FOOT_45: 45 + 10 = 55
   - NECK_SHOULDER_30: 30 + 10 = 40
   - AROMA_60: 60 + 15 = 75

8. **Validation message tiếng Việt** — error message nên là tiếng Việt cho user-facing (ví dụ: `"Mã dịch vụ đã tồn tại"`), nhưng error code constant vẫn là `SERVICE_CODE_EXISTS`.

9. **Public endpoint nhưng filter:** GET list public KHÔNG nên trả về service `isActive=false` mặc định cho khách → discuss với Vu: có cần force `isActive=true` cho public không? Hoặc để khách filter tự do, ADMIN mới thấy inactive trong UI admin?

   → Khuyến nghị: **default behavior cho public = chỉ trả về isActive=true**. Khi có JWT của ADMIN thì cho phép filter `isActive=false`. Implement bằng cách check `req.user` trong service: nếu không có user → force `isActive: true` vào filter.

   → Discuss với Vu trước khi code. Nếu không có thời gian discuss, default `isActive=true` cho public.
