## Nội dung Issue (paste nguyên văn)

## Mô tả

Implement CRUD đầy đủ cho module Supplier (Nhà cung cấp) — list, detail, create, update với search, filter, sort. Đây là **Module Kho phase 1a**: chuẩn bị nguồn cung cấp vật liệu trước khi quản lý Material (Issue #07).

**Phạm vi giới hạn:**
- ❌ KHÔNG include logic nhập hàng (purchase orders / receipts) — phase 2 Kho
- ❌ KHÔNG include payment / công nợ supplier — out of scope MVP
- ❌ KHÔNG include rating supplier — out of scope MVP

## Nghiệp vụ (User stories)

- **SUP-01 Xem danh sách:** ADMIN xem danh sách nhà cung cấp, pagination 10 items/page
- **SUP-02 Tìm kiếm:** Theo tên hoặc số điện thoại
- **SUP-03 Lọc theo trạng thái:** Filter by isActive (Active/Inactive)
- **SUP-04 Sắp xếp:** Theo name hoặc createdAt
- **SUP-05 Xem chi tiết:** ADMIN xem full info để liên hệ
- **SUP-06 Thêm nhà cung cấp:** ADMIN tạo mới
- **SUP-07 Cập nhật:** ADMIN sửa thông tin liên hệ, địa chỉ
- **SUP-08 Vô hiệu hóa:** Toggle isActive (không hard delete)

## API Endpoints

| Method | Path | Mô tả | Auth |
|---|---|---|---|
| POST | `/suppliers` | Tạo nhà cung cấp mới | `@Roles('ADMIN')` |
| GET | `/suppliers` | Danh sách (pagination + filter + search + sort) | JWT (mọi role login đều xem được) |
| GET | `/suppliers/:id` | Chi tiết | JWT |
| PATCH | `/suppliers/:id` | Cập nhật (bao gồm toggle isActive) | `@Roles('ADMIN')` |

> Không có DELETE — dùng `isActive=false` để vô hiệu hóa. Lý do: Material có ref `supplierId`, nếu xóa supplier thì invoice/import lịch sử bị broken.

## Acceptance Criteria

### A. Schema `suppliers` (MongoDB collection: `suppliers`)

```typescript
{
  name: string;              // VD: 'Công ty TNHH Tinh dầu ABC'
  contactPerson: string;     // Tên người liên hệ
  phone: string;             // Số điện thoại VN, regex 10 chữ số
  email: string;             // optional, validate format nếu có
  address: string;           // Địa chỉ đầy đủ
  taxCode: string;           // Mã số thuế, optional
  note: string;              // Ghi chú thêm, optional
  isActive: boolean;         // default true
  createdAt: Date;
  updatedAt: Date;
}
```

**Indexes cần tạo:**
- `name` (text/regex search)
- `phone` (search by phone)
- `isActive`

### B. DTOs

- [ ] `CreateSupplierDto`:
  - `name` (IsString, length 2-200)
  - `contactPerson` (IsString, length 2-100)
  - `phone` (IsString, Matches /^[0-9]{10}$/ — 10 chữ số VN)
  - `email` (IsEmail, optional)
  - `address` (IsString, length 5-500)
  - `taxCode` (IsString, optional, length max 20)
  - `note` (IsString, optional, max 1000)

- [ ] `UpdateSupplierDto`:
  - `extends PartialType(CreateSupplierDto)`
  - Thêm `isActive` (IsBoolean, optional)

- [ ] `QuerySupplierDto`:
  - `page`, `limit` (chuẩn skill)
  - `search?: string` — match `name` OR `phone` regex case-insensitive
  - `isActive?: boolean`
  - `sortBy?: 'name' | 'createdAt'` (default `createdAt`)
  - `sortOrder?: 'asc' | 'desc'` (default `desc`)

- [ ] `SupplierResponseDto`:
  - Toàn bộ field từ schema, có `@ApiProperty`

### C. SupplierService (logic)

- [ ] `create(dto)`:
  - Không cần check duplicate `name` (cho phép nhiều supplier cùng tên — vd 2 chi nhánh)
  - Có thể check duplicate `taxCode` nếu có giá trị → 409 `SUPPLIER_TAX_CODE_EXISTS`
  - Default `isActive = true`

- [ ] `findAll(query)`:
  - Build filter: search ($or `name`/`phone` regex), isActive
  - Sort, pagination

- [ ] `findOne(id)`:
  - 404 → `SUPPLIER_NOT_FOUND`

- [ ] `update(id, dto)`:
  - Verify tồn tại
  - Nếu sửa `taxCode`: check duplicate (trừ chính nó)
  - Apply dto

### D. SupplierController

- [ ] `POST /suppliers` `@Roles('ADMIN')`
- [ ] `GET /suppliers` (JWT, mọi role)
- [ ] `GET /suppliers/:id` (JWT) `ParseObjectIdPipe`
- [ ] `PATCH /suppliers/:id` `@Roles('ADMIN')` `ParseObjectIdPipe`

## Context bổ sung từ dev

**Quyết định kỹ thuật đã chốt:**

1. **Tách Supplier riêng khỏi Material** — vì user yêu cầu module Kho chia thành 2 modules. Supplier làm trước (#06), Material sau (#07, blocked by #06).

2. **Không có duplicate check trên `name`** — vì 1 công ty có thể có nhiều chi nhánh, hoặc 2 supplier khác nhau có tên giống nhau. Chỉ unique check trên `taxCode` (nếu có).

3. **`email` optional, `taxCode` optional** — vì nhỏ lẻ thường không có. Validate format nếu có giá trị.

4. **GET list cho mọi role JWT** (không chỉ ADMIN) — vì receptionist/staff có thể cần tra cứu supplier. Nếu Vu muốn restrict chỉ ADMIN, sửa khi code.

5. **Không có DELETE** — soft delete bằng `isActive=false`. Lý do: Material ref `supplierId`, nếu hard delete sẽ broken reference.

6. **Folder structure:**
   - `src/modules/supplier/` (folder English noun, collection name `suppliers`)

7. **Phone format VN** — chỉ chấp nhận 10 chữ số. Nếu cần support format quốc tế (+84), discuss với Vu. MVP: 10 số.

8. **Lưu ý cho dev:** Sau khi Issue này merge → Issue #07 Material sẽ tham chiếu `supplierId`. Đảm bảo Schema `suppliers` đã có `_id` chuẩn ObjectId trước khi bắt đầu #07.

9. **Seed 5 suppliers** đủ để cover 15 materials trong Issue #07. Phân bổ:
   - Hương Việt → tinh dầu hướng dương, olive, aroma, thảo dược
