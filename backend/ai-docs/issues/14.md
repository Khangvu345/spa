**Phạm vi giới hạn:**

## Nghiệp vụ (User stories)

- **CUST-01 Tạo khách hàng:** OPERATOR/ADMIN tạo khách mới khi tiếp nhận walk-in. Customer landing page cũng tạo qua endpoint public (booking flow)
- **CUST-02 Upsert theo SĐT:** Booking flow gọi endpoint `findOrCreateByPhone` — nếu SĐT đã có → return customer hiện hữu; nếu chưa → tạo mới với `source=ONLINE_BOOKING`
- **CUST-03 Xem danh sách:** OPERATOR/ADMIN xem list, pagination 10 items/page
- **CUST-04 Tìm kiếm:** Theo `fullName` hoặc `phone` (partial match, case-insensitive)
- **CUST-05 Lọc nguồn:** Filter theo `source` (`WALK_IN` | `ONLINE_BOOKING` | `MANUAL`)
- **CUST-06 Sắp xếp:** Theo `fullName`, `createdAt`
- **CUST-07 Xem chi tiết:** OPERATOR/ADMIN xem full info
- **CUST-08 Cập nhật:** OPERATOR/ADMIN sửa thông tin cơ bản (fullName, email, note)
- **CUST-09 Vô hiệu hóa:** ADMIN toggle `isActive` (soft delete — khách spam, blacklist)

## API Endpoints

| Method | Path | Mô tả | Auth |

| POST | `/customers` | Tạo khách hàng mới | JWT (`OPERATOR` hoặc `ADMIN`) |

## Acceptance Criteria

### A. Schema `customers` (MongoDB collection: `customers`)

```typescript
{
  fullName: string;          // 'Nguyễn Văn A' — required
  phone: string;             // 10 chữ số VN — required, UNIQUE
  email: string;             // optional, default ''
  source: 'WALK_IN' | 'ONLINE_BOOKING' | 'MANUAL';
  note: string;              // optional, default ''
  
  // Fields cho OTP — chuẩn bị sẵn, phase 3 sẽ enable
  phoneVerified: boolean;    // default false
  emailVerified: boolean;    // default false
  lastVerifiedAt: Date | null;  // default null
  
  isActive: boolean;         // default true
  createdAt: Date;
  updatedAt: Date;
}
```

**Indexes cần tạo:**
- `phone` (unique)
- `fullName` (search regex)
- `isActive`
- `source` (filter)
- Compound `(isActive, createdAt)` cho list pagination

### B. DTOs

- [ ] `CreateCustomerDto`:
  - `fullName` (IsString, length 2-100)
  - `phone` (IsString, Matches `/^[0-9]{10}$/`)
  - `email` (IsEmail, optional)
  - `source` (IsEnum CustomerSource, optional, default `MANUAL`)
  - `note` (IsString, optional, max 500)

- [ ] `FindOrCreateCustomerDto` (cho `/customers/find-or-create`):
  - `fullName` (IsString, length 2-100)
  - `phone` (IsString, Matches `/^[0-9]{10}$/`)
  - `email` (IsEmail, optional)
  - **Tự động set `source = 'ONLINE_BOOKING'`** ở service layer

- [ ] `UpdateCustomerDto`:
  - `extends PartialType(OmitType(CreateCustomerDto, ['phone']))`
  - **KHÔNG cho sửa `phone`** — phone là định danh, đổi phone = tạo customer khác

- [ ] `QueryCustomerDto`:
  - `page`, `limit` (default page=1 limit=10)
  - `search?: string` — match `fullName` OR `phone` regex case-insensitive
  - `source?: CustomerSource`
  - `isActive?: boolean`
  - `sortBy?: 'fullName' | 'createdAt'` (default `createdAt`)
  - `sortOrder?: 'asc' | 'desc'` (default `desc`)

- [ ] `CustomerResponseDto`:
  - `id, fullName, phone, email, source, note, phoneVerified, emailVerified, lastVerifiedAt, isActive, createdAt, updatedAt`
  - Tất cả field có `@ApiProperty`

- [ ] `FindOrCreateResponseDto`:
  - `extends CustomerResponseDto`
  - Thêm `wasCreated: boolean` — true nếu tạo mới, false nếu reuse customer cũ

### C. CustomerService (logic)

- [ ] `create(dto): Promise<CustomerResponseDto>`
  - Check `phone` duplicate → 409 `CUSTOMER_PHONE_EXISTS`
  - Default `source = 'MANUAL'`, `phoneVerified = false`, `emailVerified = false`, `lastVerifiedAt = null`, `isActive = true`

- [ ] `findOrCreateByPhone(dto): Promise<FindOrCreateResponseDto>`
  - Lookup theo `phone`
  - Nếu có VÀ `isActive=true` → return customer hiện hữu, `wasCreated=false`. KHÔNG override `fullName`/`email` (bảo vệ data OPERATOR đã sửa)
  - Nếu có VÀ `isActive=false` → 400 `CUSTOMER_INACTIVE`
  - Nếu không có → tạo mới với `source='ONLINE_BOOKING'`, `wasCreated=true`

- [ ] `findAll(query)`:
  - Build filter: search ($or fullName/phone regex escape ReDoS), source, isActive
  - Sort, pagination với `Promise.all([find, countDocuments])`

- [ ] `findOne(id)`: 404 → `CUSTOMER_NOT_FOUND`

- [ ] `findByPhone(phone)`: 404 → `CUSTOMER_NOT_FOUND`

- [ ] `update(id, dto)`:
  - Verify customer tồn tại
  - Apply dto (phone không trong DTO nên không sửa được)

- [ ] `toggleActive(id)`:
  - Verify customer tồn tại
  - Flip `isActive` boolean

### D. CustomerController

- [ ] `POST /customers` `@Roles('OPERATOR', 'ADMIN')`
- [ ] `POST /customers/find-or-create` `@Public()`
- [ ] `GET /customers` JWT (mọi role)
- [ ] `GET /customers/:id` JWT (mọi role) + `ParseObjectIdPipe`
- [ ] `GET /customers/by-phone/:phone` `@Roles('OPERATOR', 'ADMIN')` — validate phone regex
- [ ] `PATCH /customers/:id` `@Roles('OPERATOR', 'ADMIN')` + `ParseObjectIdPipe`

## Context bổ sung từ dev

**Quyết định kỹ thuật đã chốt:**

1. **`phone` là định danh chính + UNIQUE** — không cho 2 customer cùng phone. Booking flow luôn dùng phone làm key lookup.

2. **`findOrCreateByPhone` cho booking flow** — landing page gọi endpoint này thay vì gọi `POST /customers` thẳng. Lý do: customer cũ đã có thì tái sử dụng, không override data OPERATOR đã sửa thủ công.

3. **Fields OTP chuẩn bị sẵn nhưng default false** — phase 3 sẽ enable. Phase 1 OPERATOR tạo customer ngầm `phoneVerified=true` (đã verify qua điện thoại), customer online tạo qua landing thì `phoneVerified=false` để phase 3 verify OTP email.

4. **`source` enum:**
   - `WALK_IN` — OPERATOR tạo khi khách vãng lai
   - `ONLINE_BOOKING` — customer tự tạo qua `/find-or-create`
   - `MANUAL` — ADMIN/OPERATOR tạo thủ công (không từ booking flow, vd: VIP qua điện thoại)

5. **KHÔNG cho sửa `phone` qua PATCH** — phone là natural key. Đổi phone = tạo customer mới hoặc mở issue riêng.

6. **`/customers/find-or-create` là Public** — landing page chưa login mới gọi. Các endpoint khác đều cần JWT.

7. **Soft delete chỉ qua `isActive`** — không có audit reason cho MVP. Khi customer inactive → `findOrCreateByPhone` throw `CUSTOMER_INACTIVE` để FE hiển thị thông báo blacklist.

8. **Folder structure:** `src/modules/customer/` (flat).

9. **Lưu ý cho Khánh:** Sau khi merge issue này, Khánh dùng `customerId: ObjectId` ref `Customer` trong Invoice schema. KHÔNG cần đợi Khang xong các issue khác để code Invoice schema phần customer ref.
