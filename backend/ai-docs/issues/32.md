## Mô tả

Thêm bước xác thực **OTP qua email (Gmail)** vào luồng đặt lịch công khai: khách đặt lịch trên landing → hệ thống gửi mã OTP về email → khách nhập mã → booking mới chuyển từ `PENDING_OTP` sang `CONFIRMED`.

**Chốt provider: EMAIL qua Gmail (Nodemailer).** KHÔNG làm SMS thật (tránh đăng ký SMS Brandname). Kiến trúc dùng interface để sau mở rộng SMS được, nhưng MVP chỉ email.

**Schema đã chuẩn bị sẵn:** Booking #17 đã có status `PENDING_OTP` và `CONFIRMED` trong flow. Issue này hiện thực hóa bước chuyển giữa hai trạng thái đó.

**Phạm vi giới hạn:**
- ✅ Gửi OTP 6 số qua email (Nodemailer + Gmail App Password)
- ✅ Verify OTP → booking PENDING_OTP → CONFIRMED
- ✅ Resend OTP (có cooldown)
- ✅ Giới hạn số lần nhập sai → hủy booking
- ✅ Interface `IOtpProvider` để mở rộng (EmailOtpProvider impl; ConsoleOtpProvider cho dev)
- ❌ KHÔNG SMS thật (Viettel/VNPT) — chỉ email + console mock

## Cấu hình (đã chốt — đối chiếu business-rules.ts)

> ⚠️ **business-rules.ts hiện ghi `OTP_EXPIRY_SECONDS = 600` (10 phút).** Tóm tắt bàn giao trước đó từng ghi "3 phút". CHỐT LẠI: **dùng giá trị trong business-rules.ts (10 phút)** làm chuẩn, vì code là nguồn sự thật. Nếu muốn 3 phút → sửa hằng số, KHÔNG hardcode.

| Tham số | Giá trị | Hằng số |
|---|---|---|
| Độ dài OTP | 6 số | `OTP_LENGTH = 6` ✅ có sẵn |
| Hết hạn | 10 phút | `OTP_EXPIRY_SECONDS = 600` ✅ có sẵn |
| Số lần sai tối đa | 3 | `OTP_MAX_ATTEMPTS = 3` ✅ có sẵn |
| Cooldown resend | 120 giây | `OTP_RESEND_COOLDOWN_SECONDS = 120` ✅ có sẵn |

> Tất cả hằng số ĐÃ tồn tại trong business-rules.ts → chỉ import dùng, không thêm mới.

## Nghiệp vụ (User stories)

- **OTP-01 Gửi OTP:** Khách submit form đặt lịch → tạo booking PENDING_OTP → gửi OTP về email khách
- **OTP-02 Verify:** Khách nhập OTP đúng → booking CONFIRMED
- **OTP-03 Sai mã:** Nhập sai → tăng attempt count; đủ 3 lần sai → hủy booking (CANCELLED)
- **OTP-04 Hết hạn:** OTP quá 10 phút → verify báo hết hạn, phải resend
- **OTP-05 Resend:** Khách bấm gửi lại → OTP mới (sau cooldown 120s)

## API Endpoints

| Method | Path | Mô tả | Auth |
|---|---|---|---|
| POST | `/public/bookings/request-otp` | Tạo booking PENDING_OTP + gửi OTP email | `@Public()` |

> Lưu ý quan hệ với #17: nếu #17 đã có `POST /bookings` tạo thẳng CONFIRMED, thì khi bật OTP, luồng public chuyển sang request-otp trước. Booking operator (nội bộ) KHÔNG cần OTP — tạo thẳng CONFIRMED.

## Acceptance Criteria

### A. Schema `otp_codes` (collection mới: `otp_codes`)

```typescript
{
  bookingId: ObjectId;        // ref Booking — OTP gắn với booking nào
  email: string;              // email nhận OTP (snapshot từ booking)
  codeHash: string;           // HASH của OTP (bcrypt) — KHÔNG lưu plaintext ⚠️
  expiresAt: Date;            // createdAt + 10 phút
  attemptCount: number;       // số lần verify sai, default 0
  isUsed: boolean;            // default false; true sau khi verify thành công
  lastSentAt: Date;           // cho cooldown resend
  createdAt: Date;
}
```

**Lưu ý bảo mật:**
- ⚠️ **OTP lưu dạng HASH (bcrypt), KHÔNG plaintext.** Verify bằng bcrypt.compare. Lý do: nếu DB lộ, OTP không bị đọc trực tiếp. (Tuy là demo nhưng đây là good practice rẻ.)
- TTL index trên `expiresAt` → MongoDB tự xóa OTP hết hạn (dọn rác tự động).

**Indexes:**
- `bookingId` (lookup OTP theo booking)
- `expiresAt` TTL index `{ expireAfterSeconds: 0 }` — auto xóa khi quá hạn
- `(bookingId, isUsed)` — tìm OTP active của booking

### B. Interface + Provider (kiến trúc mở rộng)

```typescript
// otp-provider.interface.ts
export interface IOtpProvider {
  send(recipient: string, code: string): Promise<void>;
}

// email-otp.provider.ts — PRIMARY
@Injectable()
export class EmailOtpProvider implements IOtpProvider {
  // Nodemailer + Gmail, gửi email chứa mã OTP
  async send(email: string, code: string): Promise<void> { ... }
}

// console-otp.provider.ts — DEV MOCK
@Injectable()
export class ConsoleOtpProvider implements IOtpProvider {
  async send(recipient: string, code: string): Promise<void> {
    console.log(`[OTP MOCK] gửi tới ${recipient}: ${code}`);
  }
}
```
> Chọn provider qua env `OTP_PROVIDER=email|console`. Dev dùng `console` (không gửi email thật, đọc mã ở terminal). Demo dùng `email`.
> ⭐ Đây là lý do dùng interface: demo email, dev console, sau thêm SMS không phải sửa OtpService.

### D. OtpService

- [x] `generateAndSend(bookingId): Promise<void>`
  - Sinh mã 6 số ngẫu nhiên
  - Hash mã (bcrypt) → lưu `otp_codes` với expiresAt = now + 10p
  - Gọi `otpProvider.send(email, plainCode)` (gửi mã GỐC, lưu mã HASH)
- [x] `verify(bookingId, inputCode): Promise<{ confirmed: boolean }>`
  - Lookup OTP active của booking (isUsed=false)
  - Hết hạn → throw OTP_EXPIRED
  - attemptCount >= 3 → throw OTP_MAX_ATTEMPTS_EXCEEDED + hủy booking (CANCELLED)
  - bcrypt.compare(inputCode, codeHash):
    - Sai → attemptCount++; nếu đạt 3 → hủy booking; throw OTP_INVALID
    - Đúng → isUsed=true; booking PENDING_OTP → CONFIRMED; return confirmed
- [x] `resend(bookingId): Promise<void>`
  - Check cooldown: now - lastSentAt >= 120s, chưa thì throw OTP_RESEND_TOO_SOON
  - Vô hiệu OTP cũ (isUsed=true hoặc xóa) → generateAndSend mới

### E. Error Codes (THÊM MỚI)

```typescript
OTP_NOT_FOUND:              'OTP_NOT_FOUND',
OTP_EXPIRED:                'OTP_EXPIRED',
OTP_INVALID:                'OTP_INVALID',
OTP_MAX_ATTEMPTS_EXCEEDED:  'OTP_MAX_ATTEMPTS_EXCEEDED',
OTP_RESEND_TOO_SOON:        'OTP_RESEND_TOO_SOON',
OTP_SEND_FAILED:            'OTP_SEND_FAILED',
```


**Quyết định kỹ thuật đã chốt:**

1. **Email (Gmail) primary, KHÔNG SMS thật** — tránh đăng ký SMS Brandname (delay nhiều tuần, không kịp demo). Gmail App Password free, gửi được ngay.
