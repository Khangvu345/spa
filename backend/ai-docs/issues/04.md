# Issue #04: Account Management — Reset password, Lock/Unlock, Delete

> Snapshot của issue tại thời điểm dev paste vào chat AI.

---

## Nội dung Issue (paste nguyên văn)

## Mô tả

Implement chức năng quản lý tài khoản nâng cao — admin reset password, lock account, schedule delete sau 30 ngày, và flow force change password lần đăng nhập đầu sau khi reset.

## Nghiệp vụ (User stories)

- **AUTH-04 Quên mật khẩu:** User báo admin → admin reset password → user login với password mặc định → bị force đổi
- **EMP-05 Reset password mặc định:** Admin reset password của 1 nhân viên về giá trị mặc định, set `must_change_password = true`
- **EMP-06 Khóa và xóa tài khoản:** Admin lock account (không login được) → sau 30 ngày → admin có thể delete vĩnh viễn

### Flow chi tiết

**Reset password flow:**

```
User quên password → báo admin
Admin: POST /employees/:id/reset-password
System:
  - Generate password mặc định (vd: DEFAULT_RESET_PASSWORD từ env)
  - password_hash = bcrypt(default password)
  - must_change_password = true
Admin: thông báo user password mặc định
User: login với default password → BE trả token + mustChangePassword=true
FE: redirect tới trang đổi password (FORCE — không cho dùng app khác)
User: đổi password → /auth/change-password (đã có ở #02) →
  must_change_password = false
```

**Lock account flow:**

```
Admin: POST /employees/:id/lock
System:
  - account_status = LOCKED
  - locked_at = NOW
  - Confirm với admin trước khi lock (ở FE)
User: thử login → 401 generic (cùng response với sai password)
```

**Unlock account flow (bonus):**

```
Admin: POST /employees/:id/unlock
System:
  - account_status = ACTIVE
  - locked_at = null
```

**Delete account flow:**

```
Admin: DELETE /employees/:id
System validate:
  - account_status === LOCKED (không cho delete khi đang ACTIVE)
  - now() - locked_at >= 30 days (chưa đủ 30 ngày → reject)
System action:
  - account_status = DELETED
  - **KHÔNG xóa physical record** — để giữ ref cho bookings, invoices, payrolls historical
  - Soft delete: email = `${original_email}.deleted.${timestamp}` để giải phóng email cho người mới
User: KHÔNG login được nữa (account_status check)
```

## API Endpoints

| Method | Path | Mô tả | Auth |
|---|---|---|---|
| POST | `/employees/:id/reset-password` | Admin reset password về default | `@Roles('ADMIN')` |
| POST | `/employees/:id/lock` | Khóa tài khoản | `@Roles('ADMIN')` |
| POST | `/employees/:id/unlock` | Mở khóa tài khoản | `@Roles('ADMIN')` |
| DELETE | `/employees/:id` | Soft delete (sau 30 ngày lock) | `@Roles('ADMIN')` |

## Acceptance Criteria

### A. Configuration

- [ ] `.env.example` thêm:
  - `DEFAULT_RESET_PASSWORD=ChangeMe@123` (password mặc định khi reset)
  - `ACCOUNT_DELETE_AFTER_LOCK_DAYS=30`

### B. EmployeeService methods mới

- [ ] `resetPassword(staffId, adminUser): Promise<void>`
  - Verify staff tồn tại + chưa DELETED
  - Hash default password
  - Update password_hash + must_change_password = true
  - Log audit (console.log đơn giản — full audit log out of scope)
- [ ] `lockAccount(staffId, adminUser): Promise<EmployeeResponseDto>`
  - Verify staff tồn tại + account_status = ACTIVE (đã LOCKED → 400)
  - Update account_status = LOCKED, locked_at = NOW
  - **Reject nếu staffId === adminUser.id** (admin không tự lock mình)
- [ ] `unlockAccount(staffId): Promise<EmployeeResponseDto>`
  - Verify staff tồn tại + account_status = LOCKED
  - Update account_status = ACTIVE, locked_at = null
- [ ] `deleteAccount(staffId, adminUser): Promise<void>`
  - Verify account_status = LOCKED → 400 nếu không
  - Verify `now - locked_at >= 30 days` → 400 nếu chưa đủ
  - **Reject nếu staffId === adminUser.id**
  - Update account_status = DELETED, email = `${email}.deleted.${timestamp}`

### C. Update login flow ở Issue #02

- [ ] AuthService.login check: trả lỗi nếu account_status !== ACTIVE (LOCKED và DELETED đều fail) — **đã có ở #02**
- [ ] FE phía Công cần handle: response có `mustChangePassword=true` → redirect đổi password (out of scope BE)

### D. Middleware/Guard cho `must_change_password`

- [ ] Tạo `MustChangePasswordGuard`:
  - Đọc `req.user.mustChangePassword` từ JWT payload
  - Nếu true → CHỈ cho phép gọi `POST /auth/change-password` và `GET /auth/me`
  - Mọi endpoint khác → 403 với message "Vui lòng đổi mật khẩu trước khi tiếp tục"
- [ ] Apply global (sau JwtAuthGuard, trước RolesGuard):
  - `APP_GUARD: JwtAuthGuard`
  - `APP_GUARD: MustChangePasswordGuard` ← MỚI
  - `APP_GUARD: RolesGuard`

### E. Decorator để bypass MustChangePasswordGuard

- [ ] `@SkipPasswordChange()` decorator
- [ ] Apply lên `POST /auth/change-password` và `GET /auth/me`

### F. Error codes mới

- [ ] `STAFF_ALREADY_LOCKED` — lock account đã LOCKED
- [ ] `STAFF_NOT_LOCKED` — unlock account chưa LOCKED
- [ ] `STAFF_ALREADY_DELETED` — operation lên account đã DELETED
- [ ] `LOCK_DURATION_NOT_MET` — delete trước 30 ngày
- [ ] `CANNOT_OPERATE_SELF` — admin lock/delete chính mình
- [ ] `MUST_CHANGE_PASSWORD` — endpoint khác bị block

### G. Testing

- [ ] Admin reset password → user login với default → response có mustChangePassword=true
- [ ] User với mustChangePassword=true → gọi GET /employees → 403 với MUST_CHANGE_PASSWORD
- [ ] User với mustChangePassword=true → gọi POST /auth/change-password → OK, sau đó các endpoint khác work bình thường
- [ ] Admin lock account ACTIVE → user thử login → 401 generic
- [ ] Admin lock account đã LOCKED → 400
- [ ] Admin lock chính mình → 400
- [ ] Admin unlock account LOCKED → user login lại được
- [ ] Admin delete account chưa LOCKED → 400
- [ ] Admin delete account LOCKED nhưng <30 ngày → 400 với `LOCK_DURATION_NOT_MET`
- [ ] Admin delete account LOCKED >30 ngày → 200, email được suffix `.deleted.timestamp`
- [ ] Email cũ được giải phóng (test bằng cách tạo employee mới với cùng email)

## Context bổ sung từ dev

- Issue này extend EmployeeService thêm 4 methods + add 1 global guard mới (MustChangePasswordGuard). KHÔNG tạo module riêng.

- MustChangePasswordGuard thứ tự QUAN TRỌNG:
  1. JwtAuthGuard (verify JWT, gắn req.user)
  2. MustChangePasswordGuard (check mustChangePassword)
  3. RolesGuard (check role)
  Sai thứ tự → bug.

- Khi user đổi password thành công, `must_change_password` trong DB = false. Nhưng token cũ vẫn có `mustChangePassword: true` → sẽ block đến khi token expire hoặc relogin. Workaround: sau `/auth/change-password` thành công, cấp token mới + trả về cho FE.

- Self-protection: admin KHÔNG được lock/delete chính mình → tránh case lock cả 2 admin → mất quyền truy cập. Check `staffId !== adminUser.id` trong service.

- Email cấp lại sau khi DELETED: format `original@email.com.deleted.1715000000000`. Unique index của Mongo vẫn work vì email mới đã thay đổi.
