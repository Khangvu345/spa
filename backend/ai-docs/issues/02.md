# Issue #02: Module Authentication core (JWT + RBAC) + Staff schema

## Nội dung Issue (paste nguyên văn)

## Mô tả

Xây dựng module Authentication core với JWT + RBAC. Bao gồm Staff schema đầy đủ theo ERD v7 (để các issue sau extend được). Sau khi merge, toàn bộ endpoint trong app sẽ require JWT mặc định; endpoint public phải đánh dấu `@Public()`.

## Nghiệp vụ (User stories)

- **AUTH-01 Đăng nhập:** Staff login bằng `email` + `password` → server trả JWT access token
- **AUTH-02 Đăng xuất:** Client xóa token khỏi localStorage, server stateless không cần làm gì
- **AUTH-03 Đổi mật khẩu:** Staff tự đổi password của mình (cần nhập current password để verify)

> AUTH-04 (Quên password — admin reset) sẽ làm ở Issue #04.

## Database Schema — Collection `staff` (đầy đủ theo ERD v7)

| Field | Type | Constraint | Note |
|---|---|---|---|
| `_id` | ObjectId | PK | |
| `full_name` | string | required | |
| `phone` | string | required | 10 chữ số VN |
| `email` | string | required, **unique** | Dùng làm username login |
| `password_hash` | string | required | bcrypt hash |
| `role` | enum | required | ADMIN \| RECEPTIONIST \| CASHIER \| STAFF |
| `base_salary` | int | min 0, default 0 | VND |
| `work_status` | enum | required, default ACTIVE | ACTIVE \| ON_LEAVE \| RESIGNED |
| `account_status` | enum | required, default ACTIVE | ACTIVE \| LOCKED \| DELETED |
| `started_at` | Date | required | Ngày bắt đầu làm việc |
| `locked_at` | Date | nullable | NULL trừ khi account_status = LOCKED |
| `must_change_password` | boolean | required, default false | true sau khi admin reset |
| `created_at` | Date | auto | |
| `updated_at` | Date | auto | |

## API Endpoints

| Method | Path | Mô tả | Auth |
|---|---|---|---|
| POST | `/auth/login` | Đăng nhập | `@Public()` |
| GET | `/auth/me` | Thông tin staff hiện tại | JWT |
| POST | `/auth/change-password` | Đổi mật khẩu của chính mình | JWT |

> POST /auth/logout — KHÔNG có endpoint riêng. Logout = client xóa token khỏi localStorage. Stateless JWT không cần server-side action.

## Acceptance Criteria

### A. Dependencies & Configuration

- [ ] Cài: `@nestjs/jwt`, `@nestjs/passport`, `passport`, `passport-jwt`, `bcrypt`, `@types/passport-jwt`, `@types/bcrypt`
- [ ] `.env.example` thêm: `JWT_SECRET`, `JWT_EXPIRES_IN=3d`, `BCRYPT_SALT_ROUNDS=10`, `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD`, `SEED_ADMIN_FULL_NAME`, `SEED_ADMIN_PHONE`
- [ ] `JwtModule.registerAsync` với `useFactory` đọc từ `ConfigService`
- [ ] `PassportModule.register({ defaultStrategy: 'jwt' })`

### B. Staff Schema (đầy đủ theo ERD v7)

- [ ] `staff.schema.ts` flat trong `modules/employee/employee/`
- [ ] Snake_case mapping qua `@Prop({ name: '...' })`
- [ ] Timestamps option `{ createdAt: 'created_at', updatedAt: 'updated_at' }`
- [ ] Indexes: `email` unique, `account_status`, `work_status`, compound `(account_status, locked_at)`
- [ ] Enum `StaffRole`, `WorkStatus`, `AccountStatus` export từ schema (dùng chung Auth + Employee modules)

### C. JWT Strategy + Guards

- [ ] `JwtStrategy extends PassportStrategy(Strategy)`:
  - Extract từ `Authorization: Bearer <token>`
  - `ignoreExpiration: false`
  - `secretOrKey` qua `ConfigService.getOrThrow('JWT_SECRET')`
  - `validate(payload)`:
    - Query DB staff theo `payload.sub`
    - Check `account_status === ACTIVE` (KHÔNG check work_status — nhân viên tạm nghỉ vẫn có thể login để xem lịch sử)
    - Return `{ id, email, role, mustChangePassword }`
- [ ] `JwtAuthGuard extends AuthGuard('jwt')`:
  - Đọc metadata `IS_PUBLIC_KEY` → bypass nếu `@Public()`
- [ ] `RolesGuard implements CanActivate`:
  - Đọc metadata `ROLES_KEY` → check role
  - Không có `@Roles()` → cho qua (chỉ cần JWT)
- [ ] Global guards trong `app.module.ts`:
  - `APP_GUARD: JwtAuthGuard`
  - `APP_GUARD: RolesGuard`

### D. Decorators

- [ ] `@Public()` trong `auth/decorators/public.decorator.ts`
- [ ] `@Roles(...roles: StaffRole[])` trong `auth/decorators/roles.decorator.ts`
- [ ] **KHÔNG tạo** `@CurrentUser()` — dùng từ `common/decorators/`

### E. AuthService methods

- [ ] `login(dto: LoginDto): Promise<AuthResponseDto>`
  - Timing attack mitigation: luôn bcrypt.compare (dummy hash nếu user không tìm thấy)
  - Check `account_status === ACTIVE` — `LOCKED`/`DELETED` đều fail
  - Tất cả lỗi → cùng message "Email hoặc mật khẩu không đúng" (401)
  - Generate JWT, return `{ user, accessToken }`
  - **Response chứa `mustChangePassword`** để FE biết redirect nếu cần
- [ ] `getMe(staffId): Promise<StaffResponseDto>` — load fresh từ DB
- [ ] `changePassword(staffId, dto): Promise<void>`
  - Verify currentPassword đúng
  - Hash newPassword với bcrypt
  - Update `password_hash`
  - **Set `must_change_password = false`** (user đã đổi rồi)
  - newPassword phải KHÁC currentPassword → 400 nếu trùng

### F. AuthController

- [ ] `POST /auth/login` `@Public()`, body `LoginDto`
- [ ] `GET /auth/me` với `@CurrentUser()`
- [ ] `POST /auth/change-password` với `@CurrentUser()`, body `ChangePasswordDto`, return 204

### G. DTOs

- [ ] `LoginDto` — `email` (IsEmail), `password` (string, min 1)
- [ ] `ChangePasswordDto` — `currentPassword`, `newPassword` (min 8 max 128)
- [ ] `AuthResponseDto` — `user: StaffResponseDto`, `accessToken: string`
- [ ] `StaffResponseDto` — id, email, fullName, phone, role, baseSalary, workStatus, accountStatus, startedAt, mustChangePassword, createdAt, updatedAt. **KHÔNG có `passwordHash`, KHÔNG có `lockedAt`** (chỉ admin view ở Issue #04)
- [ ] Mọi field có `@ApiProperty`/`@ApiPropertyOptional`

### H. Seed Admin Script

- [ ] File `src/scripts/seed-admin.ts`:
  - Đọc credentials từ env: email, password, full_name, phone
  - Check email tồn tại → log "Skipping" exit 0
  - Tạo admin với role = ADMIN, work_status = ACTIVE, account_status = ACTIVE, started_at = today, must_change_password = false
- [ ] `package.json` thêm: `"seed:admin": "ts-node -r tsconfig-paths/register src/scripts/seed-admin.ts"`

## Context bổ sung từ dev

- Issue này là nền tảng — Staff schema sẽ được #03 và #04 extend, không được sửa schema ở 2 issues sau.

- ERD v7 đã thay đổi: thêm work_status, account_status, started_at, locked_at, must_change_password. Đã bỏ is_active.

- Roles: ADMIN = quản lý duy nhất, bao gồm cả chức năng thủ kho + dashboard tài chính + CRUD employees. Không có role HR/Warehouse Keeper riêng.

- Login check `account_status === ACTIVE` — đây là điểm dễ sai. Nhân viên `work_status = ON_LEAVE` (tạm nghỉ) VẪN login được, không lẫn lộn 2 status.

- StaffResponseDto trả về `mustChangePassword` field để FE redirect sang trang đổi password nếu true. Đây là tín hiệu duy nhất cho FE — không cần endpoint riêng.

- Pattern auth KHÁC pattern CRUD (skill spa-backend-module-pattern). Sau khi code xong, sẽ raise PR riêng update skill thêm section "Action Endpoints Pattern".

- Test timing attack qua Postman: response time login email không tồn tại vs email tồn tại sai pass phải xấp xỉ (cả 2 đều chạy bcrypt.compare).

- Folder structure: `src/modules/auth/` + `src/modules/employee/employee/` (Staff schema).
